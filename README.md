# กินดี · KinDee

แอปนับแคลอรี่และสุขภาพสำหรับคนไทย **ฟรี 100% · โอเพนซอร์ส (GPL-3.0) · ไม่มีบัญชี ไม่มีโฆษณา ไม่มีเซิร์ฟเวอร์**
ข้อมูลทั้งหมดเก็บในเครื่องของผู้ใช้ (IndexedDB) ใช้งานออฟไลน์ได้ ติดตั้งลงหน้าจอโทรศัพท์ได้ (PWA)

> English: a free, open-source, offline-first calorie & health tracker built around Thai food. React + TypeScript PWA, all data stays on-device, UI available in Thai and English. GPL-3.0-or-later. Contributions welcome: see [CONTRIBUTING.en.md](CONTRIBUTING.en.md).

สร้างแรงบันดาลใจจากฟีเจอร์ของแอปนับแคลอรี่ทั่วไป แต่ **ไม่มีการเก็บเงินหรือล็อกฟีเจอร์ใดๆ**

## สถานะปัจจุบัน (v0.5.0 — หน้าตาแบบการ์ดพาสเทล · เฟส 1 + สแกนบาร์โค้ด + แคลอรี่ด่วน/มื้อประจำ + ภาษาอังกฤษ)

### ใช้งานได้จริงและผ่านการทดสอบแล้ว

| ฟีเจอร์ | รายละเอียด |
|---|---|
| เริ่มต้นใช้งาน | กรอกข้อมูลร่างกาย → คำนวณ BMR/TDEE/เป้าแคลอรี่/สารอาหาร/น้ำ (Mifflin-St Jeor) พร้อมตรวจความสมเหตุสมผล และขั้นต่ำที่ปลอดภัย |
| บันทึกอาหาร | ฐานข้อมูลอาหารไทย/ทั่วไป 101 รายการ ค้นหา เลือกหลายรายการ ปรับจำนวน ย้อนหลังได้ มื้อเช้า/กลางวัน/เย็น/ของว่าง |
| อาหารของฉัน | สร้าง/แก้ไข/ลบอาหารเอง, รายการโปรด, รายการล่าสุด |
| สแกนบาร์โค้ด | เปิดกล้อง (ประมวลผลบนเครื่อง) อ่าน EAN-13/EAN-8/UPC → ค้นหาใน [Open Food Facts](https://world.openfoodfacts.org) → เลือกจำนวน/มื้อ → บันทึก สินค้าที่สแกนแล้วเก็บไว้ใช้ออฟไลน์ ไม่พบสินค้า/ไม่มีเน็ต/ไม่มีกล้อง = มีทางเลือกพิมพ์เลขเองหรือสร้างอาหารผูกบาร์โค้ด |
| แคลอรี่ด่วน | หน้าเพิ่มอาหาร → แท็บ "⚡ แคลอรี่ด่วน" (หรือปุ่มบนหน้าหลัก): ใส่แค่แคลอรี่ (ปุ่มค่าด่วน 100–600) ชื่อและโปรตีน/คาร์บ/ไขมันไม่บังคับ แก้แคลอรี่/ชื่อ/สารอาหารย้อนหลังได้ คัดลอกจากวันก่อนแล้วยังแก้ได้ |
| มื้อประจำ | เก็บอาหารหลายอย่างเป็นชุด (จากตะกร้าในหน้าค้นหา หรือปุ่มบุ๊กมาร์กที่หัวมื้อในไดอารี่) แล้วเพิ่มทั้งชุดลงมื้อใดก็ได้ด้วยปุ่ม + หรือปรับจำนวนส่วน (0.5–5) ก่อน แก้ชื่อ/จำนวน/เอารายการออก/ลบได้ ชุดเก็บสำเนาค่าอาหาร จึงไม่เปลี่ยนตามเมื่อแก้อาหารต้นทาง รวมอยู่ในไฟล์สำรอง (ไฟล์สำรองรุ่นเก่ายังกู้คืนได้) |
| ไดอารี่ | ดูรายวัน, คัดลอกจากวันก่อนหน้า, แก้/ลบรายการ |
| ตั้งเวลาบันทึกอัตโนมัติ | อาหารที่กินซ้ำเป็นประจำ เลือกจากค้นหาอาหาร **หรือจาก "มื้อประจำ" ที่เก็บไว้** (เพิ่มทั้งชุดทีเดียว) (ทำงานเมื่อเปิดแอปอยู่ — ดูข้อจำกัด) |
| กิจกรรม | 10 ชนิด × 3 ระดับความหนัก คำนวณ MET × น้ำหนัก × เวลา แล้วเพิ่มโควตาแคลอรี่ |
| น้ำดื่ม | ปุ่มด่วน/กำหนดเอง/ลบ, เป้าตามน้ำหนักตัว |
| น้ำหนัก | บันทึก/ย้อนหลัง/ลบ, กราฟรายสัปดาห์, BMI, ความคืบหน้า, **ปรับเป้าแคลอรี่อัตโนมัติ** (ไม่ทับค่าที่ตั้งเอง) |
| สถิติ | กราฟแคลอรี่ สัปดาห์/เดือน/ปี, สัดส่วนสารอาหาร, ข้อมูลเชิงลึกที่คำนวณจากข้อมูลจริง, ตารางสตรีค |
| รางวัล | สตรีคและเหรียญ 8 แบบ คำนวณจากข้อมูลที่บันทึก (ไม่มีการจ่ายเงินปลดล็อก) |
| เป้าหมาย/โปรไฟล์ | แก้ได้ทุกอย่าง, ตั้งแคลอรี่/น้ำเอง, พรีเซ็ตสัดส่วนสารอาหาร |
| แชร์ให้โค้ช/แพทย์ | รายงานพิมพ์เป็น PDF, CSV (เปิดใน Excel ได้), ลิงก์ + QR เปิดได้บนมือถือผู้รับโดยไม่มีเซิร์ฟเวอร์ พร้อมรหัสผ่าน (AES-256-GCM) |
| สำรอง/กู้คืน/ลบข้อมูล | ไฟล์ JSON, กู้คืนแบบทั้งหมดหรือไม่เลย (transaction), ลบทั้งหมดพร้อมยืนยัน |
| ธีม | สว่าง/มืด/ตามระบบ |
| ภาษา | **ไทย / English** สลับได้ที่หน้าต้อนรับและตั้งค่า (ค่าเริ่มต้นตามภาษาของเบราว์เซอร์) ข้อความในแอปแปลครบทุกหน้า ชื่ออาหารตั้งต้นแสดงเป็นชื่ออังกฤษ ปีแสดงเป็น พ.ศ./ค.ศ. ตามภาษา ข้อมูลที่บันทึกไม่ถูกแปลงเมื่อสลับภาษา · ข้อจำกัด: ชื่อที่ผู้ใช้ตั้งเอง (อาหาร มื้อประจำ) แสดงตามที่พิมพ์ และสินค้าจากบาร์โค้ดแสดงตามที่ Open Food Facts ให้มา |
| ออฟไลน์ | service worker แคชแอป — ทดสอบแล้วว่าตัดเน็ตแล้วเปิดและบันทึกข้อมูลได้ |

### ยังไม่มี (วางแผนเฟสถัดไป)

- **สแกนอาหารด้วย AI จากกล้อง** — ยังไม่ได้ทำ (เฟส 3: โมเดลรันบนเครื่อง)
- **Health Connect / Apple Health** — ทำบนเว็บไม่ได้ ต้องห่อเป็นแอปเนทีฟ (Capacitor) ภายหลัง
- **แจ้งเตือนผลักดัน (push)** — ยังไม่มี
- **ซิงก์ข้ามอุปกรณ์** — ตั้งใจไม่ทำ (ไม่มีเซิร์ฟเวอร์) ใช้ไฟล์สำรองย้ายเครื่องแทน

## วิธีเปิดใช้งาน (สำหรับผู้ใช้ทั่วไป)

มี 3 แบบ เลือกตามที่สะดวก

| แบบ | ทำอย่างไร | ได้อะไร / ไม่ได้อะไร |
|---|---|---|
| **A. ดับเบิลคลิก** (ง่ายสุด) | โหลด `kindee-portable-*.zip` → แตกไฟล์ → ดับเบิลคลิก `index.html` (ใช้ Chrome / Edge / Firefox) | ใช้ได้ครบ รวมกล้องสแกน/บันทึก/สำรองข้อมูล · **ไม่** ติดตั้งลงหน้าจอ, ไม่แคชออฟไลน์ผ่าน service worker, ลิงก์/QR แชร์ใช้ได้เฉพาะเครื่องนี้ |
| **B. เซิร์ฟเวอร์ในเครื่อง** | แตก `kindee-pwa-*.zip` → เปิด Terminal ในโฟลเดอร์นั้น → `python -m http.server 8080` → เปิด `http://localhost:8080` | ใช้ได้ครบรวมติดตั้งเป็น PWA บนคอมเครื่องนั้น · **มือถือเปิดผ่าน IP ในวง Wi-Fi ไม่ได้ครบ** (ไม่ใช่ HTTPS จึงไม่มีกล้อง/ติดตั้ง) |
| **C. โฮสต์บนเว็บ (HTTPS)** | อัปโฟลเดอร์ `kindee-pwa-*` ไปที่ GitHub Pages / Netlify / Cloudflare Pages | **ต้องใช้ถ้าจะใช้บนมือถือ**: ติดตั้งลงหน้าจอ, ออฟไลน์, กล้องสแกน, แชร์ลิงก์ให้คนอื่นเปิดได้ |

ข้อมูลที่บันทึกไว้เก็บแยกกันตามวิธีเปิด (A, B, C เป็นคนละที่เก็บ) ถ้าจะย้ายให้ใช้ ตั้งค่า → สำรองข้อมูล แล้วกู้คืนในที่ใหม่

## ข้อจำกัดที่ต้องรู้

1. **ตั้งเวลาบันทึกอัตโนมัติทำงานเฉพาะตอนเปิดแอป** (เบราว์เซอร์ไม่อนุญาตให้เว็บรันตอนปิดหน้า) เมื่อเปิดแอปจะบันทึกมื้อที่ถึงเวลาแล้วให้ครั้งเดียว ไม่ซ้ำ
2. **ข้อมูลอยู่ในเบราว์เซอร์เครื่องนี้เท่านั้น** ถ้าล้างข้อมูลเบราว์เซอร์/เปลี่ยนเครื่อง จะหายถ้าไม่ได้สำรอง → กด "สำรองข้อมูล" เป็นประจำ
3. **ค่าอาหารเป็นค่าประมาณ** ยังไม่ได้ตรวจทานกับตารางองค์ประกอบอาหารไทยฉบับทางการ (มีเทสต์ตรวจว่า kcal ≈ 4P+4C+9F เท่านั้น) — ถ้ามีข้อมูลที่ถูกต้องกว่า ส่ง PR ได้เลย
4. **สแกนบาร์โค้ด**: ทดสอบการอ่านบาร์โค้ดจากภาพกล้องจำลองและการแปลงข้อมูลตามรูปแบบที่เอกสาร Open Food Facts ระบุแล้ว แต่ **ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์ Open Food Facts จริง** (สภาพแวดล้อมที่พัฒนาเข้าอินเทอร์เน็ตภายนอกไม่ได้) และยังไม่ได้ลองกับกล้องมือถือจริง/ฉลากจริง ข้อมูลใน Open Food Facts มาจากอาสาสมัคร สินค้าไทยบางรายการอาจไม่มีหรือไม่ครบ ตรวจกับฉลากเสมอ
5. **ลิงก์/QR รายงาน** ผู้รับต้องเปิดผ่านเว็บที่โฮสต์แอปเดียวกัน (ลิงก์ชี้ไปที่ที่อยู่เว็บของแอป) ข้อมูลอยู่ในส่วน `#` ของลิงก์ ไม่ถูกส่งไปเซิร์ฟเวอร์ แต่ **ลิงก์ที่ไม่ตั้งรหัสผ่านใครมีก็อ่านได้** และถ้าเปิดแอปแบบดับเบิลคลิก (file://) ลิงก์จะชี้ไปที่ไฟล์ในเครื่องคุณ ส่งให้คนอื่นเปิดไม่ได้ (แอปจะเตือนในหน้าแชร์)
6. แอปให้ข้อมูลทั่วไป **ไม่ใช่คำแนะนำทางการแพทย์**

## วิธีรัน

ต้องมี Node.js 20+

```bash
npm install
npm run dev        # โหมดพัฒนา
npm run build      # สร้างไฟล์สำหรับใช้งานจริงในโฟลเดอร์ dist/
npm run preview    # ดู build ที่ http://localhost:4173
npm run build:portable   # รุ่นดับเบิลคลิกเปิดได้ (file://) ที่ dist-portable/ — ไม่มี service worker
```

นำโฟลเดอร์ `dist/` ไปวางบนโฮสต์ static ใดก็ได้ (GitHub Pages, Netlify, Cloudflare Pages, nginx) — ใช้ HashRouter และ `base: './'` จึงวางใน sub-path ได้ จากนั้นเปิดบนมือถือแล้วเลือก "เพิ่มลงหน้าจอหลัก" (Android Chrome: "ติดตั้งแอป")
**PWA ต้องเปิดผ่าน HTTPS** (หรือ localhost) จึงจะติดตั้งและใช้ออฟไลน์ได้

## การทดสอบ

```bash
npm run typecheck
npm test                         # unit + ฐานข้อมูล (vitest, 150+ เทสต์ รวมตรวจว่าข้อความทุกจุดมีคำแปล)
npm run build && npx vite preview --port 4173 &
node e2e/run.mjs onboarding      # เทสต์ในเบราว์เซอร์จริง (Playwright + Chromium)
# สถานการณ์: onboarding food schedule track insights profile share offline scan quick combo english
# (e2e ใช้ Playwright ซึ่งไม่ได้อยู่ใน dependencies: npm install --no-save playwright && npx playwright install chromium)
# รุ่นดับเบิลคลิก (file://): npm run build:portable && node e2e/portable.mjs
# (scan ต้องสร้างวิดีโอกล้องจำลองก่อน: node e2e/make-barcode-video.mjs 885100112233 e2e/fixtures/barcode.y4m)
```

เทสต์ e2e เปิดแอปจริง กดปุ่มจริง ตรวจตัวเลขที่ควรเป็น (เช่น MET×น้ำหนัก×เวลา, เป้าปรับตามน้ำหนัก, สำรอง→ลบ→กู้คืน, ลิงก์เข้ารหัสเปิดในเบราว์เซอร์ใหม่, ใช้งานตอนออฟไลน์) และจับภาพหน้าจอไว้ที่ `e2e/shots/`
ต้องติดตั้ง Playwright แยกต่างหากและแก้ path ใน `e2e/run.mjs` ให้ตรงกับเครื่องของคุณ

## สูตรที่ใช้ (เปิดเผยทั้งหมด)

- BMR (Mifflin-St Jeor): `10×กก. + 6.25×ซม. − 5×อายุ + 5` (ชาย) / `− 161` (หญิง)
- TDEE = BMR × (1.2 / 1.375 / 1.55 / 1.725 / 1.9)
- เป้าแคลอรี่ = TDEE ± (กก./สัปดาห์ × 7,700 ÷ 7) ปัดหลัก 10, ขั้นต่ำ 1,500 (ชาย) / 1,200 (หญิง)
- น้ำ ≈ 35 มล./กก. ปัดหลัก 50 · กิจกรรม = MET × กก. × ชั่วโมง · BMI ใช้เกณฑ์เอเชีย
